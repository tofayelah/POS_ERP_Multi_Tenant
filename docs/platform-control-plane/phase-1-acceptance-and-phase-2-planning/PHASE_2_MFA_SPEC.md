# KC ERP CONTROL PLANE
# PHASE 2 MULTI-FACTOR AUTHENTICATION (MFA) SPECIFICATION

**Application:** KC ERP Control Plane (`/platform`)  
**Sprint:** 2.1 (Platform Authentication, RBAC, and Session Security)  
**Standard:** RFC 6238 (TOTP: Time-Based One-Time Password Algorithm)  
**Date:** 2026-11-05  

---

## 1. MANDATORY MFA ARCHITECTURE

Multi-Factor Authentication (MFA) is strictly **MANDATORY** for all platform users across all six RBAC tiers. There is no option for a platform administrator to disable MFA.

```
+-----------------------------------------------------------------------------------+
| 1. PRIMARY AUTHENTICATION                                                         |
| - Platform Administrator enters Email and Password at `/platform/login`          |
| - Passwords verified via Argon2id / Bcrypt                                        |
+-----------------------------------------------------------------------------------+
                                          |
                                          v
+-----------------------------------------------------------------------------------+
| 2. MFA STATUS EVALUATION                                                          |
| - If MFA enrolled: Redirect to `/platform/mfa/challenge`                          |
| - If First-time login: Redirect to `/platform/mfa/setup` (Enforced onboarding)    |
+-----------------------------------------------------------------------------------+
                                          |
                                          v
+-----------------------------------------------------------------------------------+
| 3. VERIFICATION & RECOVERY                                                        |
| - User enters 6-digit TOTP code (RFC 6238)                                        |
|   OR single-use 10-character Recovery Code                                        |
| - 5 failed attempts locks MFA challenge for 15 minutes                            |
+-----------------------------------------------------------------------------------+
                                          |
                                          v
+-----------------------------------------------------------------------------------+
| 4. SESSION CERTIFICATION                                                           |
| - Session flag `platform_mfa_verified_at` set to `now()`                          |
| - User granted access to `/platform` dashboard                                    |
+-----------------------------------------------------------------------------------+
```

```sql

    ADD COLUMN IF NOT EXISTS mfa_recovery_codes JSONB NULL,        -- Array of Argon2id hashed codes
    ADD COLUMN IF NOT EXISTS mfa_failed_attempts INT DEFAULT 0,
    ADD COLUMN IF NOT EXISTS mfa_locked_until TIMESTAMPTZ NULL;
```

## 3. TOTP IMPLEMENTATION SPECIFICATION (RFC 6238)

### Algorithmic Parameters
- **Algorithm:** HMAC-SHA1 (in compliance with Google Authenticator, Microsoft Authenticator, and 1Password standard).
- **Time Step ($T_0$ / $X$):** 30 seconds.
- **Code Length:** 6 digits (numerical).
- **Clock Drift Tolerance:** $\pm 1$ time step (allows codes generated 30 seconds before or after current server time to accommodate minor client clock skew).

### Cryptographic Secret Storage
1. The TOTP shared secret (Base32 encoded, 160-bit key) is generated using a cryptographically secure pseudo-random number generator:
   ```php
   $secret = Base32::encode(random_bytes(20));
   ```
2. **At-Rest Encryption:** The secret is **never stored in plain text**. It is encrypted using Laravel's application encrypter (`AES-256-GCM` with authenticated data) before database insertion:
   ```php
   $user->mfa_secret = Crypt::encryptString($secret);
   ```

## 4. ENROLLMENT & ONBOARDING WORKFLOW

1. **Trigger:** Upon first successful primary authentication, if `mfa_enrolled_at` is null, the user is immediately redirected to `/platform/mfa/setup`. All other platform routes return HTTP 403 / redirect to setup.
2. **Visual QR Code Presentation:**
   - The UI generates an `otpauth://` URI:
     `otpauth://totp/KC%20ERP%20Control%20Plane:admin%40kcerp.com?secret={SECRET}&issuer=KC%20Retail%20ERP`
   - Rendered as an SVG QR Code directly in the browser (no third-party external chart API calls).
3. **Manual Entry Fallback:** Displays the Base32 secret formatted into 4-character blocks (e.g. `JBSW Y3DP EHPK 3PXP`) for manual entry into authenticators.
4. **Mandatory Confirmation Step:** The user must enter a valid 6-digit TOTP code generated by their app before enrollment is committed.
5. **Recovery Code Generation:** Once confirmed, the system generates **8 single-use recovery codes**, displays them to the user, and requires explicit acknowledgement ("I have saved these recovery codes").

---

## 5. RECOVERY CODE SPECIFICATION

Recovery codes provide emergency access in the event that an administrator loses access to their authenticator device.

### Format & Generation
- **Format:** 10 alphanumeric characters formatted as `XXXXX-XXXXX` (using unambiguous characters, excluding `0`, `O`, `1`, `I`, `L`).
- **Cryptographic Storage:** Recovery codes are **hashed** using Argon2id / `Hash::make()` before saving in `mfa_recovery_codes`. The server never retains plain text recovery codes.

### Consumption Rules
1. When a recovery code is used at `/platform/mfa/challenge`:
   - System verifies the input code against the stored hashes.
   - Upon a match, that specific code is **immediately deleted** from `mfa_recovery_codes` (single-use enforcement).
   - An audit event `user.mfa.recovery_code_used` is logged to `platform_audit_logs` with severity `WARNING`.
   - An emergency email alert is dispatched to the user and the Compliance Officer.
2. If remaining recovery codes fall below 3, the user is prompted to regenerate codes.

---

## 6. CHALLENGE SECURITY & RATE LIMITING

1. **Brute Force Protection:**
   - 5 consecutive invalid TOTP code attempts locks the MFA challenge for that user for 15 minutes (`mfa_locked_until = now() + 15 minutes`).
   - Rate limiting enforced in Redis: Maximum 5 attempts per IP per 5-minute window on `/platform/mfa/verify`.
2. **Replay Attack Mitigation:**
   - To prevent an intercepted TOTP code from being used twice within the 30-second window, the system records the last successfully verified time step in Redis:
     `Cache::set("mfa:used:{$user->id}:{$timeStep}", true, 60);`
   - Any subsequent attempt using the same code within that time step is rejected.
3. **Session Interceptor Middleware (`EnsurePlatformMfaVerified`):**
   ```php
   public function handle(Request $request, Closure $next): Response
   {
       if (! $request->session()->has('platform_mfa_verified_at')) {
           return redirect()->route('platform.mfa.challenge');
       }
       return $next($request);
   }
   ```
